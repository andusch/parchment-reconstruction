## Title

Compute synthetic outline IoU against caller-supplied generator polygons.

## Phase

P2

## Objective

In about two days, report intersection-over-union for polygons already in one named frame, and write the first local comparison under `benchmarks/`.

## Problem

The P2 exit requires synthetic outline agreement against generator polygons. The segmenter must not compute that score by reading BenchmarkLabel, and no outline-agreement comparison exists yet.

## User or scientific outcome

A benchmark operator can pass a predicted polygon and a generator polygon in one named frame and receive every IoU, plus a comparison file under `benchmarks/` that leaves ground-truth rows as they were.

## Inputs

- The outline-agreement metric in [EVALUATION.md](../docs/EVALUATION.md).
- Predicted polygons from [P2-03](P2-03.md) or [P2-04](P2-04.md).
- Generator polygons passed by the caller from the in-memory leaf. The solver does not load them.

## Outputs

- A pure-Python IoU function for two polygons in one named frame.
- A comparison report under a caller-supplied `benchmarks/` directory. The report includes algorithm name, version, parameter hash, code version, model hash, the absence of `random_seed`, fixture image hashes, and every IoU value. The first write states that no previous outline-agreement report exists. A later write names the previous report.

## Epistemic-class impact

no. IoU is a fixture metric. It does not re-type an outline and it does not turn a generator polygon into observed evidence.

## Schema impact

none for the project evidence database. The comparison file lives under `benchmarks/` and is not a BenchmarkLabel join, placement, or page row.

## Algorithm and benchmark impact

This is the local comparison for the `fragment_outline` algorithm from [P2-03](P2-03.md). The first report has no previous record. A second report compares against the first. Tests do not edit BenchmarkLabel rows to pass, and they introduce no IoU pass threshold.

## New dependencies

none. Polygon intersection stays in-house. No geometry library.

## Acceptance criteria

- [x] Mixed frames are refused. The function does not convert pixels to millimetres and does not open BenchmarkLabel join, placement, or page rows.
- [x] The segmenter module does not import or read the agreement report. A test may pass generator polygons into the reporter.
- [x] The report lists every IoU value. It is not summarized by its best score. No pass threshold is introduced. No human outline is a reference.
- [x] Writing the report does not edit an existing BenchmarkLabel. A second report compares against the first instead of rewriting it.
- [x] About two days. No network call.

## Tests

Synthetic polygons in a temporary `benchmarks/` directory. Two identical squares in one frame produce an IoU. A pixel polygon paired with a millimetre polygon is refused. The reporter receives generator polygons from the in-memory leaf. After the first report, a second report names the first and leaves the first file unchanged. The segmenter module does not reference the report path. Do not read `data/`, `scans/`, or `real_data/`.

## Provenance effects

The report records algorithm name `fragment_outline`, version `1`, the parameter hash, `code_version`, `model_hash` `absent`, and the absence of `random_seed`, copied from the segmentation envelope. The reporter does not invent a second envelope for the outline.
