# Task ticket

- Status: Ready
- Phase: P1

A **yes** on any stop-and-ask field means the ticket waits until an ADR and an explicit decision exist. Open questions are indexed in [OPEN_QUESTIONS.md](../docs/OPEN_QUESTIONS.md). The glossary is in [DATA_MODEL.md](../docs/DATA_MODEL.md#glossary).

## Title

Ingest local bytes: hash them, require TIFF magic, and record a checksum mismatch as an IntegrityFailure.

## Phase

P1

## Objective

Verify a local file's bytes in about one and a half days. A match returns a hash record. A mismatch returns an `IntegrityFailure` and no hypothesis. No TIFF library and no project directory.

## Problem

The roadmap requires a local folder of synthetic files to be hashed and rejected on checksum mismatch. Decoding TIFF pixels needs a library that [Q-ENG-05](../docs/ARCHITECTURE.md#q-eng-05) has not approved, and storing `originals/` would accept a project format that [Q-ENG-01](../docs/ARCHITECTURE.md#q-eng-01) has not closed.

## User or scientific outcome

An imaging operator can point the ingest use case at a file and see either a content hash or a protocol failure. The failure is not usable evidence.

## Inputs

- `SourceImage` and `IntegrityFailure` in [DATA_MODEL.md](../docs/DATA_MODEL.md).
- The TIFF and checksum rules in [SCAN_PROTOCOL.md](../docs/SCAN_PROTOCOL.md).
- Hash functions from [P1-02](P1-02.md).
- Ruling R11 and R23 in [R0-01](../docs/reviewed_resolutions/R0-01.md).

## Outputs

- A use case that reads caller-supplied bytes and returns either a verified-byte record or an `IntegrityFailure`.
- Tests for a matching hash, a mismatch, and a non-TIFF file.

## Epistemic-class impact

no. A verified byte record is the start of observed source bytes. An `IntegrityFailure` is a protocol event with no epistemic class and no hypothesis.

## Stop and ask

Answer each line `yes` or `no`. Any `yes` blocks implementation until a decision exists.

- Changes a public API: no
- Changes the project format: no

## Schema impact

none. Nothing is written under a project `originals/` directory.

## Algorithm and benchmark impact

none

## New dependencies

none. TIFF recognition is the 4-byte magic `II*\x00` or `MM\x00*`. No image library.

## Acceptance criteria

- [ ] The use case computes `sha256:` over the presented bytes and the byte length. The verified-byte id is a UUIDv5 over that content hash.
- [ ] When an expected hash is supplied and differs, the result is an `IntegrityFailure` with a random UUID, `presented_hash`, `expected_hash`, and a UTC ISO-8601 timestamp. No hypothesis is returned. The bytes are not modified.
- [ ] Media type is accepted only when the magic is little-endian or big-endian TIFF. Any other bytes fail as an unsupported media type and produce no hypothesis.
- [ ] Pixel width, pixel height, `fragment_id`, face, and `storage_path` stay absent. Header PPI is not read and does not create a calibration.
- [ ] About one and a half days. The use case makes no network call and does not write a project database.

## Tests

Synthetic byte strings, including a minimal TIFF magic prefix and a non-TIFF prefix. Do not read repository TIFF files, `data/`, `scans/`, or `real_data/`. Assert the failure is not a hypothesis and carries no epistemic class.

## Provenance effects

none on the failure path. A verified-byte record stores the content hash that a later envelope will cite. Decoder name and version wait until a TIFF decoder is approved.

## Non-goals

- A TIFF library, IFD parsing, and pixel dimensions. Those stay blocked by [Q-ENG-05](../docs/OPEN_QUESTIONS.md#q-eng-05).
- Copying bytes into `originals/` or writing `manifest.json`. The ADR-0007 layout stays proposed.
- Calibration, fragment detection, and group-scan policy. [Q-PRD-04](../docs/OPEN_QUESTIONS.md#q-prd-04) stays open.

## Required documentation

- Docstrings cite `IntegrityFailure` and the media-type rule in [docs/DATA_MODEL.md](../docs/DATA_MODEL.md#sourceimage).
- Do not describe the checksum failure as observed evidence.

## Open questions this depends on

[Q-ENG-05](../docs/OPEN_QUESTIONS.md#q-eng-05) stays open. This ticket does not close it. [Q-ENG-01](../docs/OPEN_QUESTIONS.md#q-eng-01) stays open because no project format is written.
