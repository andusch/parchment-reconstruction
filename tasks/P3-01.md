## Title

Admit catalogued and confirmed fragments under the existing fragment id rule.

## Phase

P3

## Objective

In about half a day, let a caller record `catalogued` or `confirmed` while `Fragment.create` still yields `detected`.

## Problem

Matching admits `catalogued` and `confirmed` fragments. The in-memory fragment type only stores `detected`, so a later join stage would have no legal fragment to pair. Changing the id rule, or treating identification status as observed evidence, would go past the data model.

## User or scientific outcome

A benchmark operator can record an inventory fragment as `catalogued`, or hold a reviewed detection as `confirmed`, and can still construct a machine-proposed fragment as `detected`.

## Inputs

- `Fragment` in [DATA_MODEL.md](../docs/DATA_MODEL.md#fragment), including the sentence that only `catalogued` and `confirmed` fragments enter matching by default.
- Ruling R4 in [R0-01](../docs/reviewed_resolutions/R0-01.md).
- The `detected` constructor in [src/prw/outlines.py](../src/prw/outlines.py).

## Outputs

- A `catalogued` constructor and a `confirmed` value, each with `identification_status` set to that word.
- The id remains a UUIDv5 over the caller-supplied project id and the opaque label. Status is not an id input.
- `Fragment.create` still returns `identification_status: detected`.
- Confirming a fragment returns a new value with the same id and `identification_status: confirmed`. The caller's previous value stays as it was.

## Epistemic-class impact

no. Identification status is the vocabulary the data model already assigns. This ticket does not re-type an outline, a reading, or a join, and it does not store a scholarly restoration.

## Acceptance criteria

- [x] `Fragment.create` still returns `identification_status: detected`. The id is still a UUIDv5 over the project id and the opaque label.
- [x] A catalogued fragment uses that same id rule. The same project id and label with status `detected` and status `catalogued` share an id and differ in status.
- [x] Confirming returns a new value with the same id and `identification_status: confirmed`. The previous value is unchanged.
- [x] A status outside `catalogued`, `detected`, and `confirmed` is rejected.
- [x] About half a day. No pixels are read or written. No join is proposed. No network call.

## Tests

Synthetic in-memory labels. Cover an unchanged `detected` fragment, a catalogued id that matches the project id and label, a confirmed value that keeps that id, and a rejected status. No TIFF, no project directory, and no `benchmarks/` read.
