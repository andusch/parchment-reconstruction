# Task ticket

- Phase: P2

A **yes** on any stop-and-ask field means the ticket waits until an ADR and an explicit decision exist. Open questions are indexed in [OPEN_QUESTIONS.md](../docs/OPEN_QUESTIONS.md). The glossary is in [DATA_MODEL.md](../docs/DATA_MODEL.md#glossary).

## Title

Add in-memory Fragment and FragmentOutlineRevision records for a machine outline.

## Phase

P2

## Objective

In about one day, store a machine outline as epistemic class `interpretation` and producer `machine`, with provenance and a first `StatusEvent`, without segmenting pixels.

## Problem

The package can record an assembly and a frame, and it cannot yet record a fragment or an outline revision. Segmentation needs those rows before it reads pixels. A status column on the outline, or a polygon treated as observed, would break the data model before a detector exists.

## User or scientific outcome

A benchmark operator can construct a machine outline, see class `interpretation` and producer `machine`, and append a later revision while the first polygon stays as it was.

## Inputs

- `Fragment` and `FragmentOutlineRevision` in [DATA_MODEL.md](../docs/DATA_MODEL.md).
- [ADR-0006](../docs/adr/0006-append-only-hypotheses.md).
- Envelope and `StatusEvent` from [P1-03](P1-03.md).
- Content-derived ids from [P1-02](P1-02.md).

## Outputs

- Frozen in-memory `Fragment` and `FragmentOutlineRevision` values.
- An insert that appends `proposed` in the same write.
- The outline id is a UUIDv5 over the run id and the polygon. `run_id` is set. `operator_id` and `session_id` are absent.
- A caller-supplied project id and an opaque label satisfy the fragment id rule. A machine-proposed fragment has `identification_status: detected`.

## Epistemic-class impact

no. A machine outline uses the class and producer the data model already assigns. This ticket does not re-type a reading and does not store a scholarly restoration.

none

## Acceptance criteria

- [x] Epistemic class is `interpretation` and producer is `machine`. A different class is rejected.
- [x] The envelope cited by `provenance_id` includes the parameter blob and the `sha256:` parameter hash. `model_hash` is `absent`. A deterministic outline omits `random_seed`.
- [x] The polygon cannot be replaced in place. A later revision is a new row with `supersedes_id`. The previous row stays.
- [x] The first status event is `proposed`. The outline has no status column.
- [x] The fragment id is a UUIDv5 over the caller-supplied project id and the opaque label. `identification_status` is `detected`.
- [x] About one day. No pixels are read or written. No network call.

## Tests

Synthetic in-memory polygons. Cover a rejected class, a deterministic envelope with no seed, a refused in-place polygon edit, a superseding row that leaves the first polygon intact, and a `proposed` event on insert. No TIFF, no project directory, and no `benchmarks/` read.

## Provenance effects

The outline stores `provenance_id`. Tests construct the envelope with source hashes, the full parameter blob, the `sha256:` parameter hash, algorithm name and version, `model_hash` `absent`, `code_version`, and decoder name and version. `random_seed` is omitted.

## Non-goals

- Segmentation ([P2-03](P2-03.md)), TIFF decoding ([P2-02](P2-02.md)), and calibration ([P2-04](P2-04.md)).
- Edge arcs, joins, and invalidating `EdgeArc` rows. Those rows do not exist yet.
- Human correction ([P2-06](P2-06.md)) and `identification_status: confirmed`.
- An accuracy claim against human outlines. [Q-SCI-17](../docs/OPEN_QUESTIONS.md#q-sci-17) stays open.
- Ruling, pricking, and hair/flesh side. [Q-PRD-10](../docs/OPEN_QUESTIONS.md#q-prd-10) stays open.
- A general TIFF library and a geometry library. [Q-ENG-05](../docs/OPEN_QUESTIONS.md#q-eng-05) and [Q-ENG-04](../docs/OPEN_QUESTIONS.md#q-eng-04) stay open.
- Qt, a network call, and a new runtime dependency.
- Reading `data/`, `scans/`, `real_data/`, or model weights.
- A solver path that reads the BenchmarkLabel store. Project entities do not gain `truth`, `correct_join`, or `original_text`.
