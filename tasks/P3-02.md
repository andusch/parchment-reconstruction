# Task ticket

- Status: Done
- Phase: P3

A **yes** on any stop-and-ask field means the ticket waits until an ADR and an explicit decision exist. Open questions are indexed in [OPEN_QUESTIONS.md](../docs/OPEN_QUESTIONS.md). The glossary is in [DATA_MODEL.md](../docs/DATA_MODEL.md#glossary).

## Title

Store in-memory EdgeArc, RigidTransform, and JoinHypothesis records.

## Phase

P3

## Objective

In about one day, store an edge, a rigid pose, and a pairwise join with provenance and a first `StatusEvent`, without proposing a contact.

## Problem

The package can record an outline, a score, and assembly-shaped content, and it cannot yet record an edge arc, a rigid pose, or a join. A status column, a third fragment, or a second score channel would break the data model before a proposer exists.

## User or scientific outcome

A benchmark operator can construct a machine edge and a pairwise join, see class `interpretation` on the edge and class `hypothesis` on the join and the pose, and append `proposed` or a machine `rejected` while the content row stays as it was.

## Inputs

- `EdgeArc`, `RigidTransform`, and `JoinHypothesis` in [DATA_MODEL.md](../docs/DATA_MODEL.md#edgearc), and the score-channel table in [DATA_MODEL.md](../docs/DATA_MODEL.md#score-channels).
- [ADR-0006](../docs/adr/0006-append-only-hypotheses.md) and [ADR-0009](../docs/adr/0009-separate-score-channels.md).
- `ProvenanceEnvelope`, `Score`, and `StatusStream` from [src/prw/provenance.py](../src/prw/provenance.py).
- Content-derived ids from [P1-02](P1-02.md).

## Outputs

- Frozen in-memory `EdgeArc`, `RigidTransform`, and `JoinHypothesis` values.
- An insert that appends `proposed` in the same write. The same write may instead append `rejected` when it is a machine rejection. The content row is not rewritten.
- A machine edge has epistemic class `interpretation`, producer `machine`, and a set `run_id`. Its frame is `fragment_local_mm`. Its id is a UUIDv5 over the run id, the outline revision id, and the edge geometry. `operator_id` and `session_id` are absent.
- A machine pose has epistemic class `hypothesis`, rotation, and translation. It has no scale field. Its two frames are `fragment_local_mm` frames.
- A join cites two distinct fragment ids and two distinct edge ids, one rigid pose, and one score. The score channel is `physical` and the hypothesis type is `join`. Epistemic class is `hypothesis`. The id is a UUIDv5 over the run id and the hypothesis content when `run_id` is set.
- The edge, the pose, and the join have no status column.
- `AlgorithmRun` does not gain `edge_ids`. Grouping is the edge's `run_id`. Join ids stay on the existing `join_ids` list.

## Epistemic-class impact

no. The edge, the pose, and the join use the classes the data model already assigns. This ticket does not re-type a reading and does not store a scholarly restoration.

## New dependencies

none

## Acceptance criteria

- [x] The edge class is `interpretation` and the join class is `hypothesis`. A different class is rejected. A frame other than `fragment_local_mm` is rejected for an edge and for a join pose.
- [x] A join stores two fragment ids and two edge ids. Equal fragment ids are rejected. A third fragment id is rejected.
- [x] The pose stores rotation and translation only. A scale field is rejected. The destination frame is not `page_global_mm`.
- [x] The join stores one score, with channel `physical` and hypothesis type `join`. A second channel is rejected.
- [x] The geometry, the pose, and the join content cannot be replaced in place. The first status event is `proposed`, or `rejected` for a machine rejection. The rows have no status column. A machine rejection leaves the content unchanged.
- [x] The envelope cited by `provenance_id` includes the parameter blob and the `sha256:` parameter hash. `model_hash` is `absent`. A deterministic record omits `random_seed`.
- [x] About one day. No contact is proposed. No network call.

## Tests

Synthetic in-memory geometry. Cover a rejected class, a rejected pixel frame, a rejected third fragment, a rejected scale field, a refused in-place edit, a `proposed` event on insert, and a `rejected` event that leaves the join content intact. No TIFF, no project directory, and no `benchmarks/` read.

## Provenance effects

The machine edge, the machine pose, and the join store `provenance_id`. Tests construct the envelope with source hashes, the full parameter blob, the `sha256:` parameter hash, algorithm name and version, `model_hash` `absent`, `code_version`, and decoder name and version. `random_seed` is omitted.

- Hair side, flesh side, ruling, and pricking. [Q-SCI-19](../docs/OPEN_QUESTIONS.md#q-sci-19) and [Q-PRD-10](../docs/OPEN_QUESTIONS.md#q-prd-10) stay open.

- A geometry library. [Q-ENG-04](../docs/OPEN_QUESTIONS.md#q-eng-04) stays open.
- A project directory. [Q-ENG-01](../docs/OPEN_QUESTIONS.md#q-eng-01) stays open.

- A solver path that reads the BenchmarkLabel store. Project entities do not gain `truth`, `correct_join`, or `original_text`.
- Adding `edge_ids` to `AlgorithmRun`.
