## Title

Score the `language` channel on hypotheses the physical search already admitted.

## Phase

P6

## Objective

Implement `admitted_reading_language` version `1`. Write a `language` score and a `ScreeningEvent` for hypotheses the physical gate has already seen. Leave the declared weighted sum, the language-score quality report, and calibration-uncertainty propagation unbuilt.

## Problem

[P6-01](P6-01.md) is Done. It closed [Q-SCI-05](../docs/OPEN_QUESTIONS.md#q-sci-05) and [Q-SCI-09](../docs/OPEN_QUESTIONS.md#q-sci-09) and accepted [ADR-0009](../docs/adr/0009-separate-score-channels.md) option 2. The score channel and the screening gate already exist. No stage writes a `language` score. A missing score is easy to mistake for a hypothesis the gate never saw.

## User or scientific outcome

An operator can run unfrozen `prw language` on synthetic readings. An admitted join or assembly with eligible graphemes receives one `language` score. Every offered hypothesis receives a `ScreeningEvent` of `admitted` or `excluded`. A geometry rejection stays excluded and does not become a new join. Supplied letters change a score only when the caller passes a label and a treatment, and only when eligible graphemes are already present.

## Inputs

- Andu's approval on 2026-11-18 (Asia/Hong_Kong), in the Elon · Coding chat: "Write P6-02 and open the cloud agent PR."
- Stage 9 in [ALGORITHM.md](../docs/ALGORITHM.md). Eligible grapheme text statuses are `human_read`, `unclear`, and `ocr_inferred`.
- The supplied-text rule closed by [P6-01](P6-01.md). The label and the treatment are caller text recorded in the parameter blob. This ticket does not invent a language model or a weight file.
- Existing `Score` and `ScreeningEvent` fields. The join row still stores one `physical` score from its own run. Putting a second channel on that row would mint a new join id, so this stage cites the existing hypothesis id and does not rewrite the row.

## Outputs

- Unfrozen `prw language`. It is not a stable interface. It writes no project directory and nothing under `benchmarks/`.
- Algorithm `admitted_reading_language` version `1`. The score is `eligible_nfc_code_point_count`: the number of Unicode code points in eligible grapheme texts, plus supplied letters when a label and a treatment are recorded. The count is an uncalibrated ranking feature. It is not a probability.
- `model_hash` is `absent`. `random_seed` is omitted. Decoder name and version are `absent` because the stage reads no image.
- One `ScreeningEvent` with gate `language` for each offered hypothesis. Rank stays inside one hypothesis type.

## Epistemic-class impact

no. The score is not a new reading and not a new epistemic class. Grapheme text status is not rewritten. Supplied text stays on the caller's restoration record. This stage does not store it as a grapheme. Acceptance is not involved.

## Acceptance criteria

- [x] Language scores are written only on hypotheses a physical `ScreeningEvent` already admitted, and only when those hypotheses have at least one eligible grapheme.
- [x] A `ScreeningEvent` with gate `language` is written for each offered hypothesis, with outcome `admitted` or `excluded`.
- [x] No language score is written when there are no eligible graphemes. Supplied letters do not fill that gap and are not stored as graphemes.
- [x] Supplied letters are added only with an explicit label and a recorded treatment. Those strings are in the parameter blob. Training on scholarly restoration is not added.
- [x] Language scoring does not create a join. A physical exclusion stays excluded.
- [x] The declared weighted sum, the language-score quality report, and calibration-uncertainty propagation are not implemented.
- [x] [Q-SCI-06](../docs/OPEN_QUESTIONS.md#q-sci-06) and [Q-SCI-13](../docs/OPEN_QUESTIONS.md#q-sci-13) stay open. P6 stays in progress. Version stays 0.0.0.
- [x] Default tests pass without the `htr` group, without torch, and without weights.

## Tests

Synthetic grapheme texts and one JSON request. The tests do not read `data/`, `scans/`, `real_data/`, TIFF sources from a real corpus, or model weights. `uv run pytest -m "not slow"` covers admission, exclusion, empty graphemes, supplied letters, exclusion tags, rank inside one hypothesis type, provenance, and `prw language`.

## Provenance effects

A completed run copies `admitted_reading_language` version `1`, the full parameter blob and its `sha256:` hash, `code_version`, `model_hash` `absent`, and the caller source hashes in lexicographic order. Decoder name and version are `absent`. `random_seed` is absent because the count is deterministic. The blob records the score name, the eligible text statuses, the exclusion tags, each offered reading, each supplied block, `training` `none`, `generates_graphemes` false, and `creates_joins` false. The run lists no join id, assembly id, or reading id.
