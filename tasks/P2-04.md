## Title

Establish fragment_local_mm from a caller-supplied scale without moving a later origin.

## Phase

P2

## Objective

In about one day, convert a source-pixel outline into `fragment_local_mm` when the caller supplies a scale, and leave it in pixels when they do not.

## Problem

`fragment_local_mm` does not exist until an establishing outline exists, and a pixel outline is not yet in millimetres. Estimating scale from a target is still [Q-SCI-10](../docs/OPEN_QUESTIONS.md#q-sci-10). A caller can supply a measurement while the use case recovers none.

## User or scientific outcome

A benchmark operator can supply `pixels_per_mm` and receive a millimetre outline whose frame origin stays fixed, or keep the pixel outline when no scale is supplied.

## Inputs

- `CalibrationObservation` and `CalibrationTransform` in [DATA_MODEL.md](../docs/DATA_MODEL.md).
- `CoordinateFrame.fragment_local_mm` and `with_later_outline` in [src/prw/frames.py](../src/prw/frames.py).
- [ADR-0011](../docs/adr/0011-frame-conventions.md).
- A pixel outline from [P2-01](P2-01.md) or [P2-03](P2-03.md).

## Outputs

- An observed calibration record when the caller supplies a scale.
- A new outline revision in `fragment_local_mm`. The establishing citation is fixed. A later polygon does not move the origin.
- The pixel outline, unchanged, when the caller supplies no scale.

## Epistemic-class impact

no. Calibration stays `observed`, which the data model already requires. The millimetre outline stays `interpretation` with producer `machine`. Supplying a scale does not make the outline observed.

## Acceptance criteria

- [x] `pixels_per_mm` and its uncertainty come from the caller. The use case does not read a TIFF header and does not read `millimetres_per_pixel` from the generator or from BenchmarkLabel.
- [x] Absent scale leaves the outline in `source_pixels` and does not invent a millimetre polygon.
- [x] The calibration row is epistemic class `observed`. The millimetre outline stays `interpretation` and producer `machine`, with `supersedes_id` pointing at the pixel revision. The pixel revision remains.
- [x] The stored local polygon uses the existing centroid origin, `+x` right, and `+y` down. `with_later_outline` returns the same frame id and origin.
- [x] The half-pixel center, sample coordinate `(column + 0.5, row + 0.5)`, is the named parameter `pixel_center` in the blob. About one day. No network call.

## Tests

A hand-built pixel square, plus one outline from [P2-03](P2-03.md). A caller-supplied scale produces a local polygon whose centroid is the frame origin. A second polygon leaves `establishing_outline_revision_id` and the origin unchanged. A missing scale leaves `source_pixels`. The use case does not import the generator scale constant. No `benchmarks/` read and no project directory.

## Provenance effects

The millimetre outline cites an envelope. The parameter blob includes `pixels_per_mm`, the stated uncertainty, and `pixel_center`. The hash uses the `sha256:` prefix. `model_hash` is `absent`. `random_seed` is omitted. A human-supplied calibration uses producer `human` and omits `provenance_id` on that calibration row. A machine-produced calibration includes `provenance_id`.
