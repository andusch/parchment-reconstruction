## Title

Report placement error against frozen synthetic placement labels.

## Phase

P4

## Objective

In about two days, write a local comparison under `benchmarks/` that reports root-mean-square placement error in page millimetres at a predeclared N.

## Problem

The P4 exit requires placement error on synthetic tears. [P4-04](P4-04.md) places fragments and must not score them by reading the BenchmarkLabel store. No placement-error comparison exists yet.

## User or scientific outcome

A benchmark operator can pass ranked assemblies, caller-supplied local polygons, a fragment-id correspondence, and a frozen label file, and receive every placed fragment's error in page millimetres. The label rows stay as they were.

## Inputs

- Placement error in [EVALUATION.md](../docs/EVALUATION.md#placement-error).
- The reporting list in [EVALUATION.md](../docs/EVALUATION.md#reporting).
- Frozen `kind: placement` rows in a caller-supplied `benchmarks/` directory, as written by [src/prw/synthetic_tear.py](../src/prw/synthetic_tear.py).
- The rotation rule in `_place` there. Positive rotation sends `+x` toward `+y`. The new x is `x * cos(rotation) - y * sin(rotation)`. The new y is `x * sin(rotation) + y * cos(rotation)`. The translation is added after that. The local origin is the outline centroid.
- Ranked assemblies from the caller. The order is the physical order from [P4-03](P4-03.md). This module does not import [P4-04](P4-04.md).

## Outputs

- A new module, `prw.placement_error`, with `write_placement_error`.
- N is an argument and an integer greater than or equal to 1. The report records N before it treats any label as a comparison target. The module offers no function that chooses N from the scored list or from the errors.
- The report scores the first N assemblies in the caller order. It does not reorder them by error. Assemblies past N are named as unscored.
- For one placed fragment, the landmarks are the caller-supplied local vertices in polygon order. The predicted point applies the assembly pose's rotation and translation with the `_place` matrix. The reference point applies the frozen placement row's rotation and translation with the same matrix. RMSE is the square root of the mean squared Euclidean distance over those paired vertices, in page millimetres.
- The report lists every such RMSE with its assembly id and fragment id. It does not replace that list with a single best assembly. A fragment with no correspondence, a fragment with no placement label, or an unplaced fragment is listed with no error number. The module does not write 0 for those rows. A polygon with no vertices refuses that fragment and writes no error number for it.
- The caller supplies the correspondence from project fragment id to fixture fragment id. The report records it and does not write it into `labels.json`.
- The report includes algorithm name, version, parameter hash, code version, and `model_hash` `absent`, copied from the cited assembly envelope, and the absence of `random_seed`. It includes the source hashes on that envelope and the `sha256:` digest of the label-file bytes as the freeze identifier. It names the page-origin rule recorded on that envelope. It states that the error includes the difference between that rule and the generator's absolute rotation, and that the metric does not measure warped or shrunken real parchment.
- The first report states that no previous placement-error report exists. A later report names the previous file, copies that file's error list, and leaves the previous file unchanged.
- A label file with no `kind: placement` row is refused. No error number is written. The writer does not open TIFF bytes and does not modify `labels.json` or `provenance.json`.

## Epistemic-class impact

no. Placement error is a fixture metric. It does not re-type an assembly and it does not turn a BenchmarkLabel into observed evidence.

## Acceptance criteria

- [ ] N is the caller's integer. The report records that integer. No function searches N against the errors.
- [ ] RMSE uses the `_place` matrix on the caller-supplied vertices. The report lists every scored fragment. It does not align the predicted pose to the label before the error.
- [ ] An unmatched fragment, an unplaced fragment, and a fragment with no placement label are listed with no error number.
- [ ] The correspondence and the report are not written into `labels.json`. Writing the report does not edit `labels.json` or `provenance.json`.
- [ ] A label file with no placement row is refused, and no error number is written. Join rows and page rows are not scored as placements.
- [ ] `prw.assembly_search` does not import this module. A test may pass assemblies and the correspondence into the reporter.
- [ ] The first report states that no previous placement-error report exists. A second report names the first and leaves the first file unchanged. No pass threshold is introduced.
- [ ] About two days. No network call.
