## Title

Add canonical JSON, `sha256:` hashes, and content-derived UUIDv5 identifiers.

## Phase

P1

## Objective

Provide the hash and identifier functions every later P1 record uses, in about one day, with no runtime dependency and no project store.

## Problem

Derived artifacts need identical ids when the same content is written twice. The data model specifies canonical JSON and UUIDv5, and the package scaffold does not implement either.

## User or scientific outcome

A benchmark operator can depend on repeated calls with the same content returning the same id and the same `sha256:` digest. No scholarly workflow changes.

## Acceptance criteria

- [x] Canonical JSON uses sorted object keys, UTF-8, and no insignificant whitespace. An omitted field is absent. It is not stored as null.
- [x] A hash value is `sha256:` plus lowercase hexadecimal. A hash that does not apply is the token `absent`. An empty string is not a hash value.
- [x] A content-derived id is a UUIDv5, RFC 4122, in the URL namespace `6ba7b811-9dad-11d1-80b4-00c04fd430c8`. The name is canonical JSON of the inputs the data model names for that id.
- [x] Timestamps are not inputs to an id. The same content yields the same id on a second call.
- [x] About one day. No network call. No read of `data/`, `scans/`, `real_data/`, TIFF sources, or model weights.

## Tests

Synthetic values only. Assert canonical bytes, the `sha256:` prefix, a repeated UUIDv5, and that a timestamp change does not change an id that excludes it. No project database.
