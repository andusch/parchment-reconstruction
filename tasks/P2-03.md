# Task ticket

- Status: Ready
- Phase: P2

A **yes** on any stop-and-ask field means the ticket waits until an ADR and an explicit decision exist. Open questions are indexed in [OPEN_QUESTIONS.md](../docs/OPEN_QUESTIONS.md). The glossary is in [DATA_MODEL.md](../docs/DATA_MODEL.md#glossary).

## Title

Segment one synthetic fragment into a source-pixel outline with provenance.

## Phase

P2

## Objective

In about two days, turn one verified fragment raster into a single `FragmentOutlineRevision` in `source_pixels`, or into a failed run that invents no outline.

## Problem

The roadmap exits P2 when a machine outline exists with provenance. [P2-01](P2-01.md) stores the row and [P2-02](P2-02.md) reads fixture samples. Neither traces a boundary. A failed segmentation has to remain a failed run, with no stand-in polygon.

## User or scientific outcome

A benchmark operator can point the use case at one synthetic fragment raster and receive either one interpretation outline in `source_pixels` or a failed run with no outline.

## Inputs

- Outline records from [P2-01](P2-01.md).
- The fixture reader from [P2-02](P2-02.md).
- `ingest_bytes` from [P1-05](P1-05.md).
- Stage 3, "Segment fragments," in [ALGORITHM.md](../docs/ALGORITHM.md).
- `CoordinateFrame.source_pixels` from [P1-04](P1-04.md).

## Outputs

- A headless use case. One 4-connected foreground component becomes an ordered outer polygon.
- The parameter blob names the threshold. The recorded algorithm name is `fragment_outline` and the version is `1`. Those strings are provenance labels, not a public CLI contract.
- A completed run id follows the existing id array and omits `random_seed`.

## Epistemic-class impact

no. The outline is `interpretation` with producer `machine`, which stage 3 already requires. A failed run adds no class and no outline.

## Schema impact

none. Records stay in memory. `AlgorithmRun` does not gain `outline_ids`. The outline's `run_id` groups it with the run. Join, assembly, reading, and line id lists on that run stay empty.

## Algorithm and benchmark impact

The segmenter is a new deterministic algorithm. This ticket writes no benchmark score and does not edit BenchmarkLabel rows. The comparison report is [P2-05](P2-05.md). Solver code does not read the BenchmarkLabel store.

## New dependencies

none. The boundary trace is in-house. No learned model, no Pillow, and no NumPy.

## Acceptance criteria

- [ ] A checksum mismatch or an unsupported layout returns the existing failure and no outline. Source bytes are unchanged.
- [ ] Zero foreground pixels, more than one 4-connected component, or a hole fails the run under its own id, including `attempt_id`. No placeholder polygon is returned. A later completed run of the same inputs keeps a different id.
- [ ] One component yields class `interpretation`, producer `machine`, frame `source_pixels`, and a `proposed` event. Vertices start at the topmost, then leftmost, boundary sample and follow the outer boundary, so the same mask yields the same vertex list.
- [ ] The same bytes and parameters reproduce the same polygon and the same completed run id, and do not insert a second row. The parameter blob names `foreground_threshold`. `model_hash` is `absent`. `random_seed` is omitted.
- [ ] The page mosaic from the generator, which contains several components, fails. That failure does not set `group_scan` policy and does not close [Q-PRD-04](../docs/OPEN_QUESTIONS.md#q-prd-04).
- [ ] The use case does not read `benchmarks/` and does not copy `fragment_id` from the image manifest. The fragment label is an opaque caller-supplied label.
- [ ] About two days. No network call.

## Tests

Synthetic rasters in a temporary directory, including one solid rectangle, an empty foreground, two components, a component with a hole, a checksum mismatch, and the generator's page mosaic. Assert the failed run id differs from the completed-run id of the same inputs. Assert the manifest `fragment_id` is not the stored fragment id. Do not read `data/`, `scans/`, or `real_data/`.

## Provenance effects

A completed outline cites an envelope with the source hash, the full parameter blob including `foreground_threshold`, the `sha256:` parameter hash, algorithm name `fragment_outline`, algorithm version `1`, `model_hash` `absent`, `code_version`, and the [P2-02](P2-02.md) decoder name and version. `random_seed` is omitted. A failed run records the same envelope fields and its own run id.

## Non-goals

- Millimetre conversion ([P2-04](P2-04.md)), outline IoU ([P2-05](P2-05.md)), edge descriptors, and text lines.
- Group-scan segmentation. Joins remain P3.
- An accuracy claim against human outlines. [Q-SCI-17](../docs/OPEN_QUESTIONS.md#q-sci-17) stays open.
- Ruling, pricking, and hair/flesh side. [Q-PRD-10](../docs/OPEN_QUESTIONS.md#q-prd-10) stays open.
- A general TIFF library and a geometry library. [Q-ENG-05](../docs/OPEN_QUESTIONS.md#q-eng-05) and [Q-ENG-04](../docs/OPEN_QUESTIONS.md#q-eng-04) stay open.
- Qt, a network call, and a new runtime dependency.
- Reading `data/`, `scans/`, `real_data/`, or model weights.
- A solver path that reads the BenchmarkLabel store. Project entities do not gain `truth`, `correct_join`, or `original_text`.
- Adding `outline_ids` to `AlgorithmRun`.
