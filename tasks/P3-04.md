## Title

Propose pairwise rigid joins with a physical length-difference score.

## Phase

P3

## Objective

In about two days, propose pairwise rigid joins for an admitted fragment pool, each with a `physical` score and a millimetre pose.

## Problem

Stage 5 requires `JoinHypothesis` rows ranked on the `physical` channel. Edges from [P3-03](P3-03.md) are not yet contacts. A pose in mixed units, a detected fragment in the pool, or a score tuned against BenchmarkLabel would break the contract before recall exists.

## User or scientific outcome

A benchmark operator can pass millimetre edges for catalogued or confirmed fragments and receive pairwise join hypotheses, or a completed run with an empty list when fewer than two fragments are admitted.

## Inputs

- Stage 5, "Propose pairwise rigid joins," in [ALGORITHM.md](../docs/ALGORITHM.md).
- Edges from [P3-03](P3-03.md) and join records from [P3-02](P3-02.md).
- Fragment admission from [P3-01](P3-01.md). Only `catalogued` and `confirmed` fragments enter matching by default.
- `Score` and `AlgorithmRun` in [src/prw/provenance.py](../src/prw/provenance.py).
- The calibration observation that established each fragment's millimetre frame, from [P2-04](P2-04.md).

## Outputs

- A headless use case. The recorded algorithm name is `pairwise_rigid_join` and the version is `1`. The parameter blob records the score name `negative_absolute_length_difference`. Those strings are provenance labels, not a public CLI contract.
- `detected` fragments are skipped. Their edges are not paired. Fewer than two admitted fragments completes with an empty join list and no pose.
- Each unordered pair of edges from two different admitted fragments yields two hypotheses, one per endpoint pairing. The fragment with the lesser id string is fragment A. The pose maps chord A onto chord B by a rotation that aligns A's direction with the chosen direction of B, then a translation of midpoints, from A's `fragment_local_mm` frame to B's. Both pairings share the length score and differ in the pose, so they stay two rows.
- The `physical` score is the negative of the absolute difference of the two chord lengths. It is a ranking feature. Every candidate is inserted as `proposed`. There is no residual cutoff and no machine-rejection threshold.
- A missing calibration observation, or an edge whose frame is not `fragment_local_mm`, fails the run under its own id and emits no pose.
- A completed run lists the join ids on `AlgorithmRun.join_ids`. `model_hash` is `absent`. `random_seed` is omitted. Source hashes and the decoder name and version are copied from the cited edge envelopes. Differing decoder names or versions fail the run.

## Epistemic-class impact

no. A join is `hypothesis` and an edge remains `interpretation`, which the data model already assigns. The score does not make the join observed and does not mean the edges meet.

## Algorithm and benchmark impact

`pairwise_rigid_join` is a new deterministic algorithm. This ticket writes no benchmark score and does not edit BenchmarkLabel rows. The comparison report is [P3-07](P3-07.md). This module does not import or read the BenchmarkLabel store.

## New dependencies

none. Rotation and midpoint translation stay in-house. No geometry library.

## Acceptance criteria

- [x] A self-join is absent. A `detected` fragment contributes no join. Two admitted fragments with no other partners produce joins only for that pair.
- [x] Fewer than two admitted fragments completes with an empty `join_ids` list, status `completed`, and no `attempt_id`.
- [x] Each unordered edge pair produces two `proposed` joins. Fragment A is the lesser id string. The score is the negative absolute length difference. The pose is rotation and midpoint translation between the two `fragment_local_mm` frames.
- [x] A missing calibration observation, or a pixel edge, fails the run under its own id, including `attempt_id`, and emits no pose. A later completed run of millimetre inputs keeps a different id.
- [x] The same edges, admissions, and parameters reproduce the same join ids and the same completed run id. The parameter blob names `negative_absolute_length_difference`. `model_hash` is `absent`. `random_seed` is omitted.
- [x] The module does not import or read a BenchmarkLabel file. It does not apply a rejection threshold.
- [x] About two days. No network call.

Assert this module does not reference `labels.json`. Do not read `data/`, `scans/`, or `real_data/`.

## Provenance effects

A completed join cites an envelope with the source hashes copied from the cited edge envelopes, the full parameter blob including `negative_absolute_length_difference`, the `sha256:` parameter hash, algorithm name `pairwise_rigid_join`, algorithm version `1`, `model_hash` `absent`, `code_version`, and the decoder name and version copied from those envelopes. `random_seed` is omitted. A failed run records the same envelope fields and its own run id.
