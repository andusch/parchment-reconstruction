# Task ticket

- Status: Ready
- Phase: P4

A **yes** on any stop-and-ask field means the ticket waits until an ADR and an explicit decision exist. Open questions are indexed in [OPEN_QUESTIONS.md](../docs/OPEN_QUESTIONS.md). The glossary is in [DATA_MODEL.md](../docs/DATA_MODEL.md#glossary).

## Title

Report end-to-end join presence inside a predeclared top N of assemblies.

## Phase

P4

## Objective

In about two days, write a local comparison under `benchmarks/` that reports the fraction of synthetic fixtures whose known joins appear in the top N assemblies.

## Problem

The P4 exit requires end-to-end join presence at a predeclared N. Join recall at K scores the pairwise list. It does not score assemblies. The search must not read the BenchmarkLabel store to decide which assembly to keep.

## User or scientific outcome

A benchmark operator can pass, for each fixture, the ranked assemblies, the join rows they cite, a fragment-id correspondence, and a frozen label file, and receive the fixture as present or absent. The label rows stay as they were.

## Inputs

- End-to-end join presence in [EVALUATION.md](../docs/EVALUATION.md#end-to-end-join-presence).
- The reporting list in [EVALUATION.md](../docs/EVALUATION.md#reporting).
- Frozen `kind: join` rows in a caller-supplied `benchmarks/` directory, as written by [src/prw/synthetic_tear.py](../src/prw/synthetic_tear.py).
- The previous-report pattern in [src/prw/join_recall.py](../src/prw/join_recall.py).
- Ranked assemblies and the join rows they cite, passed by the caller in physical order from [P4-03](P4-03.md). This module does not import [P4-04](P4-04.md).

## Outputs

- A new module, `prw.assembly_join_presence`, with `write_assembly_join_presence`.
- N is an argument and an integer greater than or equal to 1. The report records N before it treats any label as a comparison target. The module offers no function that chooses N from the assemblies or from the labels.
- A fixture is present when at least one frozen `kind: join` row has its unordered fragment-id pair on a join cited by one of the first N assemblies, after the caller-supplied correspondence. The metric counts fixtures. The fraction of present fixtures is that metric. The report also lists every known join as present or absent inside that top N. That list is the distribution required by the reporting section.
- A known join counts once when several top-N assemblies cite it. A hypothesis whose fragment id is absent from the correspondence does not match a label. A join id on an assembly that the caller did not pass does not count as present.
- The correspondence is recorded in the report and is not written into `labels.json`.
- The report includes algorithm name, version, parameter hash, code version, and `model_hash` `absent`, copied from the cited assembly envelope, and the absence of `random_seed`. It includes the source hashes on that envelope and the `sha256:` digest of each label file. It names the open questions that limit the claim, including that the metric does not measure a historical join on real parchment.
- The first report states that no previous end-to-end join-presence report exists. A later report names the previous file, copies that file's fixture list, and leaves the previous file unchanged.
- A caller list with no fixture is refused. A label file with no `kind: join` row is refused. No fraction is written. The writer does not open TIFF bytes and does not modify `labels.json` or `provenance.json`. Placement rows and page rows are not this metric.

## Epistemic-class impact

no. Join presence is a fixture metric. It does not re-type an assembly and it does not turn a BenchmarkLabel into a `correct_join`.

## Acceptance criteria

- [ ] N is the caller's integer. The report records that integer. No function searches N against the labels.
- [ ] A fixture is present when at least one known join pair appears on a cited join in the first N assemblies. The report lists every known join as present or absent, and it lists every fixture as present or absent.
- [ ] The correspondence and the report are not written into `labels.json`. Writing the report does not edit `labels.json` or `provenance.json`.
- [ ] A label file with no join row is refused, and no fraction is written. Placement rows and page rows are not scored.
- [ ] `prw.assembly_search` does not import this module. A test may pass assemblies, joins, and the correspondence into the reporter.
- [ ] The first report states that no previous end-to-end join-presence report exists. A second report names the first and leaves the first file unchanged. No pass threshold is introduced.
- [ ] About two days. No network call.

## Tests

Two generated leaves in a temporary `benchmarks/` directory, plus a single-leaf run. The test passes assemblies and join rows built by the caller, with a correspondence. Cover a predeclared N, a fixture counted present once, a known join counted once, a fragment id missing from the correspondence, a label file with no join row, a refused overwrite of `labels.json`, and a second report that names the first. Assert `prw.assembly_search` does not reference this module. Do not read `data/`, `scans/`, or `real_data/`.

## Provenance effects

The report copies algorithm name `rigid_assembly_search`, version `1`, the parameter hash, `code_version`, `model_hash` `absent`, and the absence of `random_seed` from the cited assembly envelope. It records the `sha256:` digest of each label file. The reporter does not invent a second envelope for the assemblies.

## Non-goals

- Changing the search so that it reads labels. [P4-04](P4-04.md) stays free of the BenchmarkLabel store.
- Defining which assemblies are distinct. [Q-SCI-08](../docs/OPEN_QUESTIONS.md#q-sci-08) stays open. N is the caller's cut of the physical order.
- Replacing join recall at K. [P3-07](P3-07.md) stays the pairwise metric.
- A pass threshold, or a claim that rank 1 is the historical page.
- A claim about a real manuscript. [Q-SCI-15](../docs/OPEN_QUESTIONS.md#q-sci-15) stays open.
- Placement error. That is [P4-05](P4-05.md).
- A `GapRegion`. [Q-SCI-13](../docs/OPEN_QUESTIONS.md#q-sci-13) stays open.
- A face constraint. [Q-PRD-03](../docs/OPEN_QUESTIONS.md#q-prd-03) stays open.
- A triple-fragment hypothesis type. [Q-SCI-07](../docs/OPEN_QUESTIONS.md#q-sci-07) stays open.
- Hair side, flesh side, ruling, and pricking. [Q-SCI-19](../docs/OPEN_QUESTIONS.md#q-sci-19) and [Q-PRD-10](../docs/OPEN_QUESTIONS.md#q-prd-10) stay open.
- A capacity or performance target. [Q-PRD-07](../docs/OPEN_QUESTIONS.md#q-prd-07) stays open.
- A geometry library. [Q-ENG-04](../docs/OPEN_QUESTIONS.md#q-eng-04) stays open.
- A project directory. [Q-ENG-01](../docs/OPEN_QUESTIONS.md#q-eng-01) stays open.
- A `language` score, channel fusion, and calibration-uncertainty propagation. Uncertainty propagation is a Phase 6 requirement.
- Qt, a network call, and a new runtime dependency.
- Reading `data/`, `scans/`, `real_data/`, or model weights.
- A solver path that reads the BenchmarkLabel store. Project entities do not gain `truth`, `correct_join`, or `original_text`.
