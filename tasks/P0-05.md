## Title

Specify the synthetic-tear fixture contract: ADR-0011 fragment-local frames, BenchmarkLabel ground truth, and the generator parameters.

## Phase

P0

## Objective

Publish the fixture rules a later generator must follow: fragment-local millimetres use the ADR-0011 centroid frame, ground truth is written only under `benchmarks/`, and missing-fragment percentage, edge erosion, rotation, and lighting variation are named parameters.

## Problem

[EVALUATION.md](../docs/EVALUATION.md) requires a manifest, generator polygons, joins, placements, scale, a parameter blob, and a seed. It does not yet require the ADR-0011 fragment-local origin and axes, and it does not name missing-fragment percentage, edge erosion, rotation, or lighting variation.

## User or scientific outcome

A benchmark operator can read one contract and know how synthetic coordinates are framed, which parameters a fixture must record, and that ground truth is a `BenchmarkLabel` under `benchmarks/`, never a row in a project database.

## Inputs

- [ADR-0011](../docs/adr/0011-frame-conventions.md). `fragment_local_mm` origin is the centroid of the establishing outline polygon, `+x` right, `+y` down, millimetres. `page_global_mm` uses the same axes.
- The synthetic-tear fixture contract and the BenchmarkLabel section in [EVALUATION.md](../docs/EVALUATION.md).
- Forbidden fields and content-derived ids in [DATA_MODEL.md](../docs/DATA_MODEL.md).
- Rulings R9, R15, and R26 in [R0-01](../docs/reviewed_resolutions/R0-01.md).
- Agent rule 13: the BenchmarkLabel store is under `benchmarks/`, outside the project evidence database, and solver code never reads it.

## Outputs

- The synthetic-tear section of [EVALUATION.md](../docs/EVALUATION.md) states the frame convention, the four generator parameters, and the BenchmarkLabel write rule.
- No generator code, no images, and no files under `benchmarks/`.

## Acceptance criteria

- [ ] The fixture contract states that `fragment_local_mm` follows ADR-0011: origin at the centroid of the establishing outline polygon, `+x` right, `+y` down, units millimetres. `page_global_mm` uses the same axes. Placements and ground-truth transforms use that convention.
- [ ] Ground truth for joins, placements, and the generator page is written only to the BenchmarkLabel store under `benchmarks/`. The contract forbids writing it into any project database. Solver code paths never read that store.
- [ ] The generator parameter blob includes configurable missing-fragment percentage, edge erosion, rotation, and lighting variation. Each is a named parameter. The blob is canonical JSON and is hashed with the `sha256:` prefix. `random_seed` is required because the generator uses randomness.
- [ ] The existing manifest remains required: page image, fragment polygons, cut curves, join set, placements in `page_global_mm`, scale, and SHA-256 digests of every generated image.
- [ ] A missing fragment is an omitted piece. It is not grapheme status `missing`. A known join is a `BenchmarkLabel`, not a `correct_join` field on a project entity.
- [ ] No application code, fixture images, or model weights are added.
