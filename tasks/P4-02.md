# Task ticket

- Status: Ready
- Phase: P4

A **yes** on any stop-and-ask field means the ticket waits until an ADR and an explicit decision exist. Open questions are indexed in [OPEN_QUESTIONS.md](../docs/OPEN_QUESTIONS.md). The glossary is in [DATA_MODEL.md](../docs/DATA_MODEL.md#glossary).

## Title

Record a screening event for a hypothesis a gate has seen.

## Phase

P4

## Objective

In about half a day, store a `ScreeningEvent` with gate `physical`, `language`, or `human`, and outcome `admitted` or `excluded`.

## Problem

Stage 6 requires a `ScreeningEvent` with gate `physical` for each join the assembly search admits or excludes. The data model defines the row. The package has no such value. An exclusion has to stay distinguishable from a join the gate never saw.

## User or scientific outcome

A benchmark operator can record that a run admitted or excluded a join at the physical gate, and can read that event back by its content-derived id.

## Inputs

- `ScreeningEvent` in [DATA_MODEL.md](../docs/DATA_MODEL.md#screeningevent).
- Stage 6 in [ALGORITHM.md](../docs/ALGORITHM.md).
- Content-derived ids from [src/prw/identity.py](../src/prw/identity.py).

## Outputs

- A new module, `prw.screening`, with a frozen `ScreeningEvent` and a `ScreeningLog`.
- The id is a UUIDv5 over the array `run_id`, `hypothesis_id`, `gate`, `outcome`, in that order.
- `gate` is `physical`, `language`, or `human`. `outcome` is `admitted` or `excluded`. Any other word is rejected.
- The row has no status column, no epistemic class, and no score.
- `ScreeningLog.append` stores the event. A second event with the same id is refused. The log does not rewrite the hypothesis the event cites.

## Epistemic-class impact

no. A screening event is not a hypothesis and does not re-type one. Admission is not acceptance, and exclusion is not a `ValidationDecision`.

Answer each line `yes` or `no`. Any `yes` blocks implementation until a decision exists.

## Schema impact

none. Records stay in memory. The ADR-0007 directory is not written.

## Algorithm and benchmark impact

none. This ticket does not decide which joins are admitted. [P4-04](P4-04.md) writes the physical-gate events. No score is written under `benchmarks/`.

## New dependencies

none

## Acceptance criteria

- [ ] A physical admission and a physical exclusion each round-trip through the log. The id changes when the outcome changes.
- [ ] A gate outside `physical`, `language`, and `human` is rejected. An outcome outside `admitted` and `excluded` is rejected.
- [ ] The event has no status column and no score. Appending it does not change the cited hypothesis.
- [ ] A second append of the same id is refused.
- [ ] About half a day. No search runs. No network call.

## Tests

In-memory ids. Cover both physical outcomes, a rejected gate word, a rejected outcome word, and a refused duplicate. No TIFF, no project directory, and no `benchmarks/` read.

## Provenance effects

none. The event stores `run_id`. It does not grow a provenance envelope.

## Non-goals

- Deciding admission. That is [P4-04](P4-04.md).
- Writing a `language` or `human` outcome from a scorer. The type allows those gate names. Phase 6 owns language scoring. [Q-SCI-05](../docs/OPEN_QUESTIONS.md#q-sci-05) and [Q-SCI-09](../docs/OPEN_QUESTIONS.md#q-sci-09) stay open.
- A reason string, a face field, or a new epistemic class on the event.
- A `GapRegion`. [Q-SCI-13](../docs/OPEN_QUESTIONS.md#q-sci-13) stays open.
- A triple-fragment hypothesis type. [Q-SCI-07](../docs/OPEN_QUESTIONS.md#q-sci-07) stays open.
- Hair side, flesh side, ruling, and pricking. [Q-SCI-19](../docs/OPEN_QUESTIONS.md#q-sci-19) and [Q-PRD-10](../docs/OPEN_QUESTIONS.md#q-prd-10) stay open.
- A capacity or performance target. [Q-PRD-07](../docs/OPEN_QUESTIONS.md#q-prd-07) stays open.
- A geometry library. [Q-ENG-04](../docs/OPEN_QUESTIONS.md#q-eng-04) stays open.
- A project directory. [Q-ENG-01](../docs/OPEN_QUESTIONS.md#q-eng-01) stays open.
- Channel fusion and calibration-uncertainty propagation. Uncertainty propagation is a Phase 6 requirement.
- Qt, a network call, and a new runtime dependency.
- Reading `data/`, `scans/`, `real_data/`, or model weights.
- A solver path that reads the BenchmarkLabel store. Project entities do not gain `truth`, `correct_join`, or `original_text`.
