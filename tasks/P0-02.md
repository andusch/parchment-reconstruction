## Title

Confirm the scan protocol and the privacy policy: lossless TIFF, checksum failures, and no network.

## Phase

P0

## Objective

Check that capture and privacy documents treat masters as immutable lossless TIFF, record a checksum mismatch as an `IntegrityFailure` outside the evidence pool, and keep the default process local. Fix only a mismatch.

## Problem

Ingest later depends on a capture contract and on the privacy policy. If either document calls a checksum failure observed evidence, or allows a lossy master, the evidence chain is already wrong before code exists.

## User or scientific outcome

An imaging operator can see which files are usable evidence. A later reader can see that unpublished scans stay local and that a failed checksum never enters the evidence pool.

## Acceptance criteria

- [x] The scan protocol requires a lossless TIFF master, records SHA-256 outside the pixels, and rejects any other media type at ingest.
- [x] A checksum mismatch records an `IntegrityFailure` and does not repair bytes in place. The failure is not observed evidence and does not enter the evidence pool.
- [x] A claimed resolution in the file header never populates calibration. The importer warns and leaves calibration absent.
- [x] The privacy policy states a single-user local tool, no telemetry, and no network client in the default process.
- [x] The policy forbids agent reads of `data/`, `scans/`, `real_data/`, TIFF sources, and model weights, and points at the gitignore exclusions.
- [x] About one day. No TIFF library is named.
