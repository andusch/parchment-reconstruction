## Title

Report join recall at a predeclared K against frozen synthetic join labels.

## Phase

P3

## Objective

In about two days, write a local comparison under `benchmarks/` that reports join recall at a predeclared K and names the previous record when one exists.

## Problem

The P3 exit requires join recall at K against the frozen `BenchmarkLabel` store, compared with the previous record when one exists. [P3-04](P3-04.md) proposes joins and must not score them by reading that store. No join-recall comparison exists yet.

## User or scientific outcome

A benchmark operator can pass ranked joins and a frozen label file and receive every known synthetic join as present or absent in the top K, plus a comparison file that leaves the label rows as they were.

## Inputs

- Join recall at K and the reporting list in [EVALUATION.md](../docs/EVALUATION.md#join-recall-at-k).
- Frozen `kind: join` rows in a caller-supplied `benchmarks/` directory, as written by [src/prw/synthetic_tear.py](../src/prw/synthetic_tear.py).
- Ranked joins from [P3-05](P3-05.md). The proposals themselves come from [P3-04](P3-04.md) and are passed in by the caller.
- The outline-agreement report pattern in [P2-05](P2-05.md): a new file, a named previous file, and no rewrite of the previous file.

## Outputs

- A comparison report under the caller-supplied `benchmarks/` directory. K is an argument. The report records K before it treats any label as a comparison target. K is an integer greater than or equal to 1. This module offers no function that chooses K from the scored list.
- Recall is the fraction of frozen join labels whose unordered fragment-id pair appears on at least one of the top K ranked joins. The caller supplies a correspondence from project fragment id to fixture fragment id. The correspondence is recorded in the report and is not written into `labels.json`. A hypothesis whose fragment id is absent from the correspondence does not match a label.
- A known join counts once when several top-K hypotheses share its fragment pair. The report lists every known join as present or absent. It is not summarized by a best score. No pass threshold is introduced.
- The report includes algorithm name, version, parameter hash, code version, and `model_hash` `absent`, copied from the cited join envelope, and the absence of `random_seed`. It includes the source hashes on that envelope and the `sha256:` digest of the label-file bytes as the freeze identifier. It names the open questions that limit the claim, including that the metric does not measure a historical join on real parchment.
- The first report states that no previous join-recall report exists. A later report names the previous file, copies that file's recall list, and leaves the previous file unchanged.
- A label file with no `kind: join` row is refused. No recall number is written. The writer does not open TIFF bytes and does not modify `labels.json` or `provenance.json`.

## Epistemic-class impact

no. Recall is a fixture metric. It does not re-type a join and it does not turn a BenchmarkLabel into observed evidence or into a `correct_join`.

## New dependencies

none

## Acceptance criteria

- [ ] K is the caller's integer. The report records that integer. No function searches K against the scored joins.
- [ ] Recall uses the unordered fragment-id pair after the caller-supplied correspondence. A known join in the top K counts once. The report lists every known join as present or absent.
- [ ] The correspondence and the report are not written into `labels.json`. Writing the report does not edit `labels.json` or `provenance.json`. Overwriting `labels.json` is refused.
- [ ] A label file with no join row is refused, and no recall number is written. Placement and page rows are not scored.
- [ ] The proposer module does not import or read the report or the label file. A test may pass proposals and the correspondence into the reporter.
- [ ] The first report states that no previous join-recall report exists. A second report names the first and leaves the first file unchanged. No pass threshold is introduced.
- [ ] About two days. No network call.

## Tests

A generated leaf in a temporary `benchmarks/` directory, with joins proposed from caller-built catalogued fragments and a correspondence supplied by the test. Cover a predeclared K, a known join counted once, a fragment id missing from the correspondence, a label file with no join row, a refused overwrite of `labels.json`, and a second report that names the first. Assert the proposer module does not reference the label path. Do not read `data/`, `scans/`, or `real_data/`.

## Provenance effects

The report copies algorithm name `pairwise_rigid_join`, version `1`, the parameter hash, `code_version`, `model_hash` `absent`, and the absence of `random_seed` from the cited join envelope. It records the `sha256:` digest of the label file. The reporter does not invent a second envelope for the joins.
