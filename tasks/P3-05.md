## Title

Derive join rank inside one run on the physical channel.

## Phase

P3

## Objective

In about one day, derive join order when a list is read, without storing rank and without computing a new score.

## Problem

Rank exists only inside `(run, hypothesis_type, channel)` and is not a column. [P3-02](P3-02.md) can hold a `physical` score and cannot yet order joins. Storing rank, dropping `rejected`, or sorting joins together with assemblies would change the rank rule.

## User or scientific outcome

A benchmark operator can pass join rows, their scores, their runs, and their status events, and receive the `physical` order for one completed run.

## Inputs

- The rank paragraph in [DATA_MODEL.md](../docs/DATA_MODEL.md#score-channels).
- [ADR-0003](../docs/adr/0003-evidence-classes-and-ranked-hypotheses.md) and [ADR-0009](../docs/adr/0009-separate-score-channels.md).
- Join rows from [P3-02](P3-02.md). Scores may be caller-supplied. This ticket does not require [P3-04](P3-04.md).

## Outputs

- A pure ordering of joins that have a `physical` score with hypothesis type `join`, whose run is absent or `completed`, and whose latest status is not `invalidated`.
- A higher score is earlier. Equal scores are ordered by the content-derived hypothesis id, ascending bytewise.
- Position in that sequence is the rank. Rank is not written onto the join, and it is not an input to the join id.
- A join whose latest status is `rejected` stays in the order. The written rule omits `invalidated` only.
- A join with no status event is refused. The data model calls that row invalid.
- A request to order joins together with assemblies or readings fails. No fused key is produced.

## Epistemic-class impact

no. Ordering does not change epistemic class, producer, or the meaning of a hypothesis. Rank 1 remains a hypothesis.

## New dependencies

none

## Acceptance criteria

- [ ] A higher `physical` score precedes a lower one. Equal scores follow hypothesis id, ascending bytewise.
- [ ] An invalidated join is omitted. A join from a `failed` or `cancelled` run is omitted. A `rejected` join stays in the order.
- [ ] A join with no `physical` score is omitted. A join with no status event is refused.
- [ ] The returned order is not written back onto the join. Repeating the call leaves the join id unchanged.
- [ ] A list that mixes joins with assemblies or readings fails. No cross-type order is returned.
- [ ] About one day. No network call.

## Tests

Synthetic in-memory joins with caller-supplied scores. Cover a higher score first, an id tie-break, an omitted invalidated join, an omitted failed-run join, a retained rejected join, a missing status event, and a refused mix of joins and assemblies. No TIFF, no project directory, and no `benchmarks/` read.

## Provenance effects

none. The function reads envelopes and scores the caller already stored. It does not invent a second envelope.

## Non-goals

- Computing the length-difference score ([P3-04](P3-04.md)) and writing join recall ([P3-07](P3-07.md)).
- A stored rank column, a rank input to the hypothesis id, and a fused sort. [Q-SCI-09](../docs/OPEN_QUESTIONS.md#q-sci-09) stays open.
- Omitting `rejected` or `contested` beyond the written rule. `contested` is an assembly status.
- A triple-fragment hypothesis type. [Q-SCI-07](../docs/OPEN_QUESTIONS.md#q-sci-07) stays open.
- Hair side, flesh side, ruling, and pricking. [Q-SCI-19](../docs/OPEN_QUESTIONS.md#q-sci-19) and [Q-PRD-10](../docs/OPEN_QUESTIONS.md#q-prd-10) stay open.
- A capacity or performance target. [Q-PRD-07](../docs/OPEN_QUESTIONS.md#q-prd-07) stays open.
- A geometry library. [Q-ENG-04](../docs/OPEN_QUESTIONS.md#q-eng-04) stays open.
- A project directory. [Q-ENG-01](../docs/OPEN_QUESTIONS.md#q-eng-01) stays open.
- Assemblies, a `language` score, channel fusion, and calibration-uncertainty propagation. Uncertainty propagation is a Phase 6 requirement.
- A claim that rank 1 is the historical join on real parchment.
- Qt, a network call, and a new runtime dependency.
- Reading `data/`, `scans/`, `real_data/`, or model weights.
- A solver path that reads the BenchmarkLabel store. Project entities do not gain `truth`, `correct_join`, or `original_text`.
