## Title

Search rigid non-overlapping page assemblies and keep the top N on the physical channel.

## Phase

P4

## Objective

In about three days, build rigid assemblies from admitted pairwise joins inside a caller-supplied page frame, and keep at most N of them.

## Problem

Stage 6 requires up to N `AssemblyHypothesis` rows in the one shared `page_global_mm` frame. Joins from [P3-04](P3-04.md) are pairwise poses between fragment frames. Nothing yet places those poses on the page, rejects positive-area overlap, or records N. A near-duplicate filter, a warp, or a page size read from BenchmarkLabel would go past the contract.

## User or scientific outcome

A benchmark operator can pass pairwise joins, millimetre outlines for catalogued or confirmed fragments, a `PageFrame`, N, and two pose tolerances, and receive at most N non-overlapping assemblies. When none can be placed, the run completes with an empty assembly list and the screening events for the joins it considered.

- Option 1 of [ADR-0008](../docs/adr/0008-rigid-rectangular-page.md), as a labeled working assumption. The ADR stays Proposed.

## Outputs

- A new module, `prw.assembly_search`. The recorded algorithm name is `rigid_assembly_search` and the version is `1`.
- The parameter blob records `score` as `join_score_sum_minus_range_penalty`, the caller integer `n`, `page_origin` as `minimum_corner`, `anchor` as `least_fragment_id_bytes`, `anchor_rotation_radians` as `0`, `translation_tolerance_mm`, `rotation_tolerance_radians`, `page_frame_id`, and the four page-range numbers. Those fields are the parameters. A hash of them is not a substitute.
- N is an integer greater than or equal to 1. A boolean, a missing N, a missing tolerance, or a negative tolerance fails the run and emits no assembly.
- Each join the caller passes gets one `ScreeningEvent` with gate `physical` on a completed run. A join is `excluded` when its latest status is `invalidated`, its run is `failed` or `cancelled`, either fragment is absent from the outline pool, either fragment is not `catalogued` or `confirmed`, or it has no single `physical` score of type `join`. Otherwise it is `admitted`. A join with no status event, or a join that cites no run, fails the run and emits no assembly.
- A candidate is one non-empty subset of admitted joins. Subsets are generated in lexicographic order of their join ids, sorted by ascending UUID bytes. The empty subset is not a candidate.
- A subset is kept when its joins place every one of its fragments, the poses agree within the caller tolerances, and the placed polygons have no positive-area overlap. Boundary contact is allowed. A disconnected subset is dropped. A dropped subset is not inserted and is not a `rejected` assembly.
- The anchor is the placed fragment with the least id bytes. Before the final shift its page rotation is 0 and its translation is `(0, 0)`.
- The walk visits the subset's joins in ascending id-byte order. It places a fragment when exactly one endpoint is already placed. The join pose maps fragment A's local frame onto fragment B's local frame. When A is already placed, B's page pose is A's page pose composed with that join pose. When B is already placed, A's page pose is B's page pose composed with the inverse of that join pose.
- When both endpoints are already placed, the relative pose implied by the two page poses must match the join pose. The rotation residual is the smallest absolute difference after adding or subtracting two pi. The translation residual is the Euclidean distance in page millimetres. Both residuals must be less than or equal to the caller tolerances. A subset that never places every one of its fragments is disconnected and is dropped.
- After every fragment in the subset is placed, add one translation to every pose so the minimum placed vertex x and the minimum placed vertex y are 0. Do not rotate again. Overlap is tested on those shifted polygons. Positive area is overlap. The test lives in this module. It does not import `prw.outline_agreement`.
- `join_ids`, `unplaced_fragment_ids`, and placements are stored in ascending UUID-byte order. Unplaced ids are the admitted outline-pool fragments this assembly did not place. `detected` fragments are not in that pool and are not listed as unplaced.
- The `physical` score of type `assembly` is the sum of the member joins' `physical` scores minus the range penalty. The penalty is 0 when the shifted width lies inside the page width range and the shifted height lies inside the page height range, both inclusive. Otherwise it is the total millimetres of shortfall and excess on width and on height. The score is one number. It is not a probability and it does not mean the historical page size was recovered. A second channel is not written.
- Equal scores keep the ascending id-byte order from [P4-03](P4-03.md). There is no second sort key and no near-duplicate drop. The run inserts the first N assemblies in that order. A candidate past N is not inserted. When fewer than N candidates are kept, the run inserts all of them and still records the caller N.
- Each inserted assembly is `proposed`. When a contained join's latest status is `rejected` or `rejected-via-ValidationDecision`, the same write then appends `contested`. The assembly row is not rewritten.
- A completed run with no kept candidate has an empty `assembly_ids` list and still stores the screening events. It does not insert a one-fragment assembly.
- A missing page frame, a frame other than `page_global_mm`, an outline that is not `fragment_local_mm`, or disagreeing decoder names or versions fails the run under its own id and emits no assembly and no screening event.
- `model_hash` is `absent`. `random_seed` is omitted. Source hashes are the sorted union of the cited join envelopes. The decoder name and version are copied from those envelopes when they agree.

## Epistemic-class impact

## Acceptance criteria

- [ ] N, both tolerances, and the four page ranges are in the parameter blob beside `join_score_sum_minus_range_penalty`. The run records `model_hash` `absent` and omits `random_seed`.
- [ ] Each considered join has one physical screening event. An invalidated join and a `detected` fragment's join are `excluded`. A join with no status event fails the run and emits no assembly.
- [ ] A kept assembly uses page-frame poses, has no positive-area overlap, and lists the admitted fragments it did not place. The minimum placed vertex sits at `(0, 0)`.
- [ ] The inserted rows are the first N in `physical_assembly_order`. A later candidate is absent. Equal scores follow ascending id bytes. No pose-distance filter runs.
- [ ] An assembly that contains a `rejected` join is `contested` after `proposed`. The content row is unchanged.
- [ ] No kept candidate completes with an empty assembly list and the screening events. A one-fragment assembly is absent.
- [ ] A BenchmarkLabel path is not an input. The import walk does not reach the generator or the recall writers.
- [ ] About three days. No network call. No timing bound and no fragment-count bound.

## Tests

Caller-built joins and rectangles in memory. Use at most four admitted joins so the power set stays small. Cover one non-overlapping pair, one positive-area overlap that is dropped, a disconnected pair of joins that is dropped, an N of 1 that inserts only the first ranked assembly, an equal-score tie broken by id bytes, a rejected join that makes the assembly `contested`, an invalidated join that is `excluded`, an empty completion when every subset overlaps, a failed run when N is missing, and an import walk that does not load `prw.synthetic_tear`. Do not read `data/`, `scans/`, `real_data/`, or a fixture `labels.json` from this module.
