## Title

Build chord edge arcs from one millimetre outline.

## Phase

P3

## Objective

In about one day, turn one `fragment_local_mm` outline into chord `EdgeArc` rows, or into a completed run that emits none.

## Problem

Stage 4 requires edge arcs in `fragment_local_mm` before any join can name them. [P3-02](P3-02.md) stores the row and does not trace a polygon side. A pixel edge, or a new descriptor entity, would mix frames or change the schema.

## User or scientific outcome

A benchmark operator can pass one millimetre outline and receive one machine edge per usable side, or a run that leaves the outline in place and emits no edge.

## Inputs

- Stage 4, "Build edge descriptors," in [ALGORITHM.md](../docs/ALGORITHM.md).
- `EdgeArc` records from [P3-02](P3-02.md).
- A machine outline already in `fragment_local_mm` from [P2-04](P2-04.md), including that outline's provenance envelope.
- `CoordinateFrame.fragment_local_mm` from [P1-04](P1-04.md).

## Outputs

- A headless use case. Each side of the polygon, including the side that closes the ring, is one chord: the ordered endpoints in `fragment_local_mm`.
- The recorded algorithm name is `edge_chord` and the version is `1`. The parameter blob records `descriptor` as `chord` and records `minimum_edge_length_mm`. Those strings are provenance labels, not a public CLI contract.
- A side whose length is greater than or equal to `minimum_edge_length_mm` becomes one `EdgeArc`. A shorter side is omitted. A side of length zero is omitted, including when the minimum is zero.
- The edge producer is `machine`, `run_id` is set, and the first status event is `proposed`. Source hashes, decoder name, and decoder version are copied from the outline envelope. `model_hash` is `absent`. `random_seed` is omitted.
- An outline whose frame is not `fragment_local_mm` fails the run under its own id and emits no edge.
- An outline with no usable side completes with an empty edge list. The outline stays. This use case emits no join.

## Epistemic-class impact

no. An edge is `interpretation` with producer `machine`, which stage 4 already requires. A failed run adds no class and no edge.

## Schema impact

none. Records stay in memory. The descriptor name lives in the parameter blob. `AlgorithmRun` does not gain `edge_ids`. The edge's `run_id` groups it with the run. Join, assembly, reading, and line id lists on that run stay empty.

## Algorithm and benchmark impact

`edge_chord` is a new deterministic algorithm. This ticket writes no benchmark score and does not edit BenchmarkLabel rows. Join recall is [P3-07](P3-07.md). Solver code does not read the BenchmarkLabel store.

## New dependencies

none. Endpoint and length arithmetic stays in-house. No geometry library.

## Acceptance criteria

- [x] A pixel outline, or any other non-millimetre frame, fails the run under its own id, including `attempt_id`. No edge is returned. A later completed run of the same inputs keeps a different id.
- [x] One quadrilateral in `fragment_local_mm` yields four edges when every side meets the recorded minimum. The closing side is included. Vertices stay in outline order.
- [x] A side shorter than `minimum_edge_length_mm` is omitted. A zero-length side is omitted when the minimum is zero. A negative minimum is rejected.
- [x] An outline whose every side is too short completes with no edges and leaves the outline unchanged.
- [x] The same outline and parameters reproduce the same edge ids and the same completed run id. The parameter blob names `descriptor` and `minimum_edge_length_mm`. `model_hash` is `absent`. `random_seed` is omitted.
- [x] The use case does not read `labels.json` and does not emit a join.
- [x] About one day. No network call.

Cover four sides, a short side, a zero-length side, a negative minimum, an empty completed run, and a failed pixel-frame run whose id differs from the completed-run id of a millimetre outline. Assert the module does not reference `labels.json`. Do not read `data/`, `scans/`, or `real_data/`.

## Provenance effects

A completed edge run cites an envelope with the source hashes copied from the outline envelope, the full parameter blob including `descriptor` and `minimum_edge_length_mm`, the `sha256:` parameter hash, algorithm name `edge_chord`, algorithm version `1`, `model_hash` `absent`, `code_version`, and the decoder name and version copied from that same envelope. `random_seed` is omitted. A failed run records the same envelope fields and its own run id.

- A separate descriptor entity. The chord is the edge geometry plus the parameter name `chord`.
- A triple-fragment hypothesis type. [Q-SCI-07](../docs/OPEN_QUESTIONS.md#q-sci-07) stays open.
- Hair side, flesh side, ruling, and pricking. [Q-SCI-19](../docs/OPEN_QUESTIONS.md#q-sci-19) and [Q-PRD-10](../docs/OPEN_QUESTIONS.md#q-prd-10) stay open.

- A geometry library. [Q-ENG-04](../docs/OPEN_QUESTIONS.md#q-eng-04) stays open.
- A project directory. [Q-ENG-01](../docs/OPEN_QUESTIONS.md#q-eng-01) stays open.
- Assemblies, a `language` score, channel fusion, and calibration-uncertainty propagation. Uncertainty propagation is a Phase 6 requirement.

- Adding `edge_ids` to `AlgorithmRun`.
